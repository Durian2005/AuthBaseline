## 二、Stage 0 · 管线等价性（正确性证据）

**要证明的事**：C# 引擎（OpenCvSharp YuNet + CvDnn ArcFace）与 Python 参考管线
（cv2 FaceDetectorYN + onnxruntime）对同一张图算出的嵌入逐位等价。

**为什么必须有它**：P2 起，登录判定、审计、阈值全部建立在"C# 引擎输出的特征"上。
若 C# 的预处理（对齐参考点 / (x−127.5)/128 / RGB 序 / LMEDS）与参考实现有偏差，
公开基准上 ArcFace 的分数就**不属于我们** —— 那是一条会骗人的证据链。

**做法**：每张图跑两遍（`AuthServer.exe --faceid-embed <img>` 与 Python 参考管线），
比余弦。判据 min(cos) ≥ 0.999。

**实测（2026-10-18 复跑）**：

| 项 | 结果 |
|----|------|
| 有效帧（检出人脸） | **58/58**（`left-ok` 真人帧回放样本 46 帧 + `_static` 静态夹具 12 帧） |
| min(cos) | **1.000000**（frame_0000.jpg） |
| 无脸帧（_smoke） | 8/8 正确跳过（两条管线都返回"无脸"） |

**结论**：C# 实现与参考实现逐位等价。P0-4 的 LFW 数字因此**就是线上引擎的数字**，
Python 侧评测没有"测了一套、线上跑另一套"的漏洞。

## 三、LFW 子集评测 · 基线数字

**数据**：LFW（lfw-deepfunneled），本机 `.workbuddy/tmp/lfw/`，**绝不入库**。
**配对**：正样本 = 同一人两张不同图；负样本 = 两个不同人的图。
固定种子 20261018，各 1500 对，缓存 3612 张图。

| 指标 | 数值 | 说明 |
|------|------|------|
| 平均准确率 @ 默认阈值 0.50 | **96.83%** | 判据 ≥99%，未达 |
| EER | **1.87%**（阈值 0.132） | \|FAR−FRR\| 最小点 |
| TAR @ FAR=1e-4 | **97.93%**（阈值 0.207） | 约 2% 真人被拒 |
| TAR @ FAR=1e-5 | 97.93%（阈值 0.209） | ⚠️ 负样本仅 1500 对，此为外推，见第五节 |
| 正样本余弦 min / mean | **−0.093 / 0.659** | 存在同人负余弦对（差异极大的照片） |
| 负样本余弦 max / mean | **0.209 / 0.005** | 负样本侧分离度良好 |

**读数要点**：
- 负样本侧非常干净（mean 0.005、max 0.209）—— ArcFace 对"不像的人"判得很死，
  这对双胞胎类难负样本是有利的（SFace 对照见下节）。
- 精度差距几乎全部来自**正样本侧压不到阈值以上**（mean 0.659，min 甚至为负）。
- 默认阈值 0.50 既不是 EER 点（0.132）也不是 FAR=1e-4 点（0.207）——
  P0-2 里"0.50 只是起点、必须由 P3 实测定档"的判断得到数据支持。

## 四、诊断 · 精度上限来自对齐，不是模型

LFW 上 ArcFace 的公开成绩在 99.5% 量级，我们只有 96.83%。
以下对照实验按顺序排除了"管线写错"与"模型选错"，把瓶颈定位到**五点对齐质量**。

### 4.1 排除管线实现错误（6 组对照，均无实质差异）

| # | 对照 | 结果 |
|---|------|------|
| 1 | 检测输入：拉伸到 640×480 vs 保留原生尺寸 | 无差异 |
| 2 | 参考点集（arcface_dst 等）× 关键点顺序 4 组合 | dst38 as-is 最优，差异 <0.01 |
| 3 | 对齐估计器（LMEDS/RANSAC）× 归一化 9 组合 | 均 ~0.64，无组合能救 |
| 4 | ONNX 元数据 | 无内嵌预处理信息可抄 |
| 5 | 输入上采样 1×/2×/3× | 无差异 |
| 6 | 多人脸选脸策略（32% 的配对图有多张脸）：center vs largest | 仅 +0.005 |

### 4.2 SFace 对照实验（决定性证据）

同一套 YuNet 五点对齐，只换识别模型：

| 指标 | ArcFace（本模块） | SFace（2FA 现用） |
|------|------|------|
| 正样本余弦 mean | 0.659 | 0.650 |
| 负样本余弦 mean / max | 0.005 / 0.209 | 0.088 / **0.386** |

**解读**：
- 正样本均值两者持平（0.65 上下）⇒ 0.65 是"**YuNet 五点对齐质量**"的共同上限，
  不是 ArcFace 管线写错的症状。对齐把同一张脸的不同照片扭曲到了
  特征空间里拉不近的程度。
- 负样本侧 ArcFace **明显占优**（max 0.209 vs 0.386）⇒ 换模型对"双胞胎"类
  难负样本是有意义的选择，P0-1 的选型决策成立。

### 4.3 真人同会话帧的行为模式（与 P2 设计互证）

对 left-ok 真人样本（转头序列）算自相似度：

- 相邻正脸帧：0.95–0.97；
- 转头至侧脸：最低降到 **0.151**；
- 回正后：恢复到 0.845–0.94。

与 P2 设计（采集**正脸单帧**、灰区回退口令）互证：侧脸帧自然落入低分区，
不会靠"运气"蒙过阈值；同时也说明**采集时机引导**（回正再采）比调阈值更关键。

### 4.4 遗留改进杠杆（P3 候选，不引入）

buffalo_l 包自带的 `2d106det.onnx`（106 点关键点）可在五点对齐前精修关键点，
预期直接抬升 4.1/4.2 定位的对齐瓶颈。未引入原因：106→5 的索引映射需要重新标定，
属于新的正确性风险，应作为独立阶段单独验证（含 Stage 0 式对照）。

## 五、对 P3（阈值定档）的输入与统计告诫

1. **工作点建议输入**：若按 FAR=1e-4 定档，阈值 ≈ **0.207**，TAR ≈ 97.93%
   ⇒ 约 2% 的真人尝试落入灰区、转口令登录。配合灰区 ±0.05（P0-2 默认），
   灰区为 [0.157, 0.257]，宽度是否可接受需 P3 连同锁策略一起评估。
2. **统计功效告诫**：负样本只有 1500 对，FAR=1e-4 对应 0.15 个越界样本 ——
   已到分辨率边缘；TAR@FAR=1e-5 纯属外推。P3 定档前应扩大负样本集
   （LFW 全量 mismatch 对，或换 IJBB/IJBC 协议），否则"FAR=1e-4"是个
   没有置信区间的数字。
3. **基准难度告诫**：LFW 是正面、棚拍的简单基准；真实登录场景
   （运动模糊、侧脸、光照、低端摄像头）只会更难。线上数字应以
   P3 装机实测为准，本报告数字是**下界参考**，不是线上承诺。

## 六、P0-5 · 纯逻辑单测（46 项新增）

三个文件，全部只测不碰 IO 的逻辑（无摄像头/无模型文件/无 Mongo，CI 可跑）：

| 文件 | 覆盖 | 关键断言 |
|------|------|----------|
| `StubFaceIdEngineTests.cs` | 假引擎四行为开关、采集链形状、Derive、Similarity 数学 | ★ engine_down 三层全断；★ 同身份派生逐位相同、跨身份 \|cos\|<0.2；尺度不变；零向量/长度不符 ⇒ 0 |
| `FaceIdOptionsTests.cs` | 默认值、环境变量覆盖、路径解析 | 不变文化解析、垃圾值保持默认、无环境变量时恒等变换 |
| `FaceIdDecisionTests.cs` | 阈值/灰区三途边界（P2 服务层将调用的纯函数） | ★ 三边精确位置（0.55/0.45 含）；★ 负灰区不得 fail-open；NaN fail closed；结论单调不减 |

**总结果**：127/127 通过（81 旧 + 46 新），无新增编译警告。

### 6.1 本阶段抓到并修复的真 bug：Derive 的 NaN 污染

`StubFaceIdEngine.Derive` 原实现用 `BitConverter.ToSingle` 直接解释 SHA-256 字节：

- **NaN 污染**：约 0.8% 的字节组落在 IEEE-754 单精度 NaN/Inf 编码区。
  向量里一个 NaN 就让点积整体变 NaN ⇒ 同身份余弦从 1.0 变 NaN ⇒
  `FaceIdDecision` 判 Mismatch ⇒ **本人被拒**。假引擎"确定性通过路径"整体失效。
- **量级失控**：float32 位模式横跨 ~1e-38~1e38，余弦被少数极端坐标主导，
  实测跨身份 \|cos\| 最大 0.36，"近乎正交"的注释名不副实。

**修复**：改为"4 字节按无符号整数读 → 线性映射 [-1,1)"。修复后实测：
同身份余弦 1.0（双精度 epsilon 内）、190 个跨身份组合 \|cos\| 最大 0.12 / 均值 0.038、
全有限。三个回归断言（6.1 表）钉死该方案，防止退回去。

> 这个 bug 只有单测能抓到：它不影响编译、不影响真引擎、只在探针跑到
> "录入→验证"时以"本人被拒"的形式出现。它是"纯逻辑单测必须跟进模块"
> 而不是等探针的一个具体例证。

## 七、已知边界与风险（交付口径）

- ⚠️ **96.83% 是 LFW 子集上的数字**，不是线上承诺；真实场景只会更难（第五节）。
- ⚠️ **默认阈值 0.50 未定档**：P3 之前，任何人脸登录尝试的通过率都只是工程默认值。
- ⚠️ **负样本 1500 对的 FAR 估计到 1e-4 已是边缘**，1e-5 是外推（第五节）。
- ✅ 管线正确性已证（Stage 0 min cos = 1.000000），公开基准分数归属于我们。
- ✅ 引擎不可用时 fail closed 且显式降级留痕（P2 控制器负责写审计）。
- ⚠️ 人脸接口的"未鉴权面"与 2FA 模块同样存在，已登记，**不宣称已解决**。
