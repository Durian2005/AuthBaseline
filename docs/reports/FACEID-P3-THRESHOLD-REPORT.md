## 二、口径修正：阈值 = 通过线（先正名，再定档）

P2 的判定式是：

```csharp
if (sim >= threshold + grayBand) return Pass;   // 旧
```

也就是说界面上写着"判定阈值 0.50"，**实际要 0.55 才放行**。同一个数字在代码与界面里指两件事，而定档恰恰是"拿实测曲线反推一个数"——这种歧义必然算错一档。

P3 改成：

```csharp
if (sim >= threshold)            return Pass;   // 新：阈值即通过线
if (sim >= threshold - grayBand) return GrayZone;
return Mismatch;
```

> 这不是"放宽了行为"就完事：**旧档位的真实通过线是 0.55，新档位是 0.30**。报告里所有"定档前"的数字都按 0.55 算。

## 四、定档决策

**取 `Threshold = 0.30`，`GrayBand = 0.05`。**

三个理由：

1. **FAR 1e-4 需要 0.2668，往上取一档到 0.30**。取整方向朝"更严"，因为线上是 **1:N**（每人最多 3 张模板取最大余弦），最大统计量会把 FAR 抬高（3 张时上限约 3 倍量级）。0.30 在 1:1 下是 2e-5，留出的余量正好覆盖这个放大。
2. **不取 0.35 及以上**：0.35 的 TAR 已经掉到 98.13%，再往上掉得更快（0.45 ⇒ 95.5%），而 FAR 一分钱都没省（都是 0，因为已经低于分辨率）。
3. **灰区宽度不动（0.05）**：灰区只影响"计不计失败"，不影响"能不能进"。0.25–0.30 这段在 LFW 上攻击者命中率仅 1.6e-4，本人掉进来却不罕见；把下沿放在 0.25 意味着**只有明确低于 0.25 才计一次失败**。代价是攻击者在这条窄带里试不触发锁窗 —— 0.05 是"少锁真人"与"别给试探留太宽地带"之间的折中，**不随阈值一起调**。

## 七、口径（别说满）

1. **LFW 是简单集**（正脸、光照正常、单人）。这里的 FAR/TAR **不是线上估计**，更不能当成"识别认证"的结论。真实场景（手举照片、室内杂光、侧脸）一定更差。
2. **5 万负对下 FAR=1e-5 只是外推**：分母不够，尾部形状看不出来。要谈 1e-5 得换更大的负样本集（如 IJB-C / 自建）。
3. **1:N 的 FAR 比 1:1 高**，本报告的曲线是 1:1；0.30 的余量是**估计**，不是实测。
4. **不是 PAD**：活体默认关闭，阈值调得再准也改变不了"照片即本人"这个事实。
